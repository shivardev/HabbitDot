# Architecture

HabbitDot is an Expo SDK 57 React Native application built around a local SQLite data store.

## Design principles

- Offline by default: core behavior has no network dependency.
- Local scheduling: Android receives native local notifications rather than remote pushes.
- Derived analytics: charts are computed from stored habit and completion data, not duplicated in a reporting database.
- Safe upgrades: the Android application identifier remains stable so `adb install -r` preserves application data.

## Runtime flow

```text
User interface
    |-- creates and edits habits ------> SQLite
    |-- records completions -----------> SQLite
    |-- reads analytics inputs --------> SQLite
    `-- requests reminder changes -----> Notification scheduler
                                             |
                                             `--> Android notification service
```

## Main modules

- `App.tsx` owns navigation and the primary habit-management experience.
- `src/database.ts` owns schema initialization, persistence, and data queries.
- `src/notifications.ts` owns permission handling, Android channels, reminder scheduling, and cancellation.
- `src/AnalyticsScreen.tsx` derives and renders statistics from the local records.

## Notifications

Reminder instances are tied to a habit and its daily target. A reminder is unnecessary once the target has already been met for that date. Scheduling code should remain deterministic, cancellable, and resilient to app restarts.

## Native projects

The `android` and `ios` directories are generated by Expo prebuild and are intentionally ignored. Native configuration belongs in `app.json` and supported Expo config plugins so a clean prebuild remains reproducible.
